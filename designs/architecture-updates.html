Architecture Migration · v1 → Lean v2

What changed, and why

From an 8–9 agent production-grade simulation to a lean 4-agent system that leans on Claude Code + git

Guiding principle
Never add a layer that simulates infrastructure you already have

v1 was designed like a cloud multi-agent platform squeezed into a single-developer Claude Code setup — write-through memory stores, per-call audit logs, hand-rolled version history, an LLM driving production traffic. v2 deletes everything that re-implemented what Claude Code and git already provide: sub-agents whose final message returns to the parent, deterministic hooks, a scoped tool surface, and git for versioning + diffs. Smaller surface, fewer failure modes, and it actually runs.

2 critical correctness fixes
Bugs in v1 that would have stopped it working at all
These were not preferences — v1's wave tracking literally could not function with them in place.
Fix A · memory had no writer
Write-through commit path didn't exist
v1 blocked agents from writing memory and told them to "propose; a hook commits" — but no hook committed anything, and the HOOK_CALLER distinction relied on an env var Claude Code never sets. So currentWave, status, and innerLoopCount were read by hooks but written by no one. v2: the Orchestrator (main session) is the sole writer of the control-plane hub; sub-agents return JSON as their final message and write their own durable artifacts to git. Nothing to "commit".
Fix B · logger races + bloat
PostToolUse logger wrote memory every call
v1 logged a versioned diff into working-memory.json on every tool call, async. Concurrent writes to one JSON file = races + corruption, and the file bloated until the Orchestrator re-read it each stage — undoing the compression win. v2: the per-call logger is deleted. The audit trail is git history plus the Claude Code transcript. One writer, no races.

What v1 got right and v2 preserves
Hooks ↔ skills separation
Deterministic enforcement (hooks) kept distinct from model judgment (skills). The single strongest decision in the design.
Deterministic vs judgment review
CI (no LLM) vs AI Review (judgment) — same principle, now CI is hooks instead of a fake agent.
Confidence + risk tags
HIGH/MED/LOW and risk:high drive where the human looks and force gates.
Output compression
Agents return signal JSON, not prose — now a real win with the per-call logger gone.
Narrow tool surface per agent
Each agent is path/tool scoped; the PreToolUse guard enforces it deterministically.
Loop caps + human gates
Every loop is bounded; escalation to a human is the explicit exit, never silent retry.
